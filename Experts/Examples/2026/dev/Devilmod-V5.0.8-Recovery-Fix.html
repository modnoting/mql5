1. ปัญหาที่พบ (Root Causes)

BUG ปัญหาที่ 1: Recovery Entry Price ไม่ Offset

ตำแหน่ง: Lines 597, 638, 694, 743

อาการ: RECOVERY BUY/SELL เปิดที่ currentAsk/currentBid ตรงๆ ไม่ offset จากราคา entry ของ position ที่กำลังขาดทุน

// โค้ดเดิม (V5.0.8) - ผิด ExtTrade.Buy(oppositeLot, _Symbol, currentAsk, 0, 0, ...); // ← เปิดที่ราคาตลาด = จุดเดียวกับ SELL ที่ขาดทุน ExtTrade.Sell(oppositeLot, _Symbol, currentBid, 0, 0, ...); // ← เปิดที่ราคาตลาด = จุดเดียวกับ BUY ที่ขาดทุน // โค้ดใหม่ (V5.09 Fix) - ถูก double recoveryEntry = lastRecoverySell - OppositeRecoveryDistance * _Point; ExtTrade.Buy(oppositeLot, _Symbol, recoveryEntry, recoverySL, recoveryTP, ...);

ผลกระทบ: RECOVERY BUY เปิดที่ ~4570.975 (จุดเดียวกับ SELL ที่ขาดทุน ~2000 pts) → SL ถูก hit ซ้ำๆ ~10+ ครั้ง แต่ละครั้ง损失 ~2000-3000 pts กับ lot 2.0

BUG ปัญหาที่ 2: SL=0, TP=0 สำหรับ Recovery Orders

ตำแหน่ง: ทุก Recovery order placement (4 จุด)

อาการ: Recovery orders ไม่มี Stop Loss หรือ Take Profit

// โค้ดเดิม ExtTrade.Buy(oppositeLot, _Symbol, currentAsk, 0, 0, ...); // ← SL=0, TP=0 = ไม่มีการป้องกัน // โค้ดใหม่ double recoverySL = StopLong(recoveryEntry, (int)dynamicSL); double recoveryTP = TakeLong(recoveryEntry, (int)g_pips_120); ExtTrade.Buy(oppositeLot, _Symbol, recoveryEntry, recoverySL, recoveryTP, ...);

ผลกระทบ: Recovery positions ไม่มี SL = ขาดทุนไม่จำกัด, ไม่มี TP = ไม่รู้จุดทำกำไร

BUG ปัญหาที่ 3: Layer Counter ไม่รีเซ็ตถูกต้อง

ตำแหน่ง: Lines 537-539

อาการ: g_oppositeLayerCount ถูกรีเซ็ตเป็น 0 เมื่อ existingOpposite == 0 แต่ counter นี้อาจค้างอยู่เมื่อ recovery positions ถูกปิดโดย SL

ผลกระทบ: Layer counter อาจไม่accurate ทำให้คำนวณ Lot ผิด

3. สิ่งที่แก้ไข (Fixes Applied)

FIX Fix 1: Recovery Entry Offset Price

คำนวณราคา Entry ของ Recovery order โดย offset จาก:

  • BUY RECOVERY (เมื่อ SELL ขาดทุน): recoveryEntry = lastRecoverySell - OppositeRecoveryDistance * _Point
  • SELL RECOVERY (เมื่อ BUY ขาดทุน): recoveryEntry = lastRecoveryBuy + OppositeRecoveryDistance * _Point
  • Layer 1 SELL RECOVERY: recoveryEntry = currentBid + OppositeRecoveryDistance * _Point
  • Layer 1 BUY RECOVERY: recoveryEntry = currentAsk - OppositeRecoveryDistance * _Point

ผลลัพธ์: Recovery orders จะเปิดที่ราคาที่ offset จาก position ที่ขาดทุน ไม่ใช่ที่ราคาตลาดเดียวกัน

FIX Fix 2: SL/TP สำหรับ Recovery Orders

ใช้ฟังก์ชันเดียวกับ Normal trades:

  • recoverySL = StopLong(recoveryEntry, (int)dynamicSL) สำหรับ BUY
  • recoverySL = StopShort(recoveryEntry, (int)dynamicSL) สำหรับ SELL
  • recoveryTP = TakeLong(recoveryEntry, (int)g_pips_120) สำหรับ BUY
  • recoveryTP = TakeShort(recoveryEntry, (int)g_pips_120) สำหรับ SELL

ผลลัพธ์: Recovery orders มี SL/TP ชัดเจน ไม่ขาดทุนไม่จำกัด

FIX Fix 3: Enhanced Logging

เพิ่มข้อมูลใน Print log:

  • Entry= ราคา Entry ที่คำนวณได้
  • SL= ราคา Stop Loss
  • TP= ราคา Take Profit

ผลลัพธ์: สามารถ debug ได้ง่ายขึ้นจาก Journal

4. ตัวอย่างผลลัพธ์หลังแก้ไข

สมมติ: SELL Entry ที่ 4580.00, ขาดทุน -2000 pts

รายการก่อนแก้ (V5.0.8)หลังแก้ (V5.09)
RECOVERY BUY Entry 4570.975 (市场价格 = จุดเดียวกับ SELL) 4568.00 (4580.00 - 1200 pts offset)
RECOVERY BUY SL 0 (ไม่มี SL) 4567.00 (dynamicSL คำนวณ)
RECOVERY BUY TP 0 (ไม่มี TP) 4572.00 (g_pips_120 คำนวณ)
สถานการณ์ ทั้ง SELL และ BUY ขาดทุนที่จุดเดียวกัน BUY ต่ำกว่า SELL → hedge ได้ผลเมื่อราคาลง
