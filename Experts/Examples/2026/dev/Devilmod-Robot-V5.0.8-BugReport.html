Bug #4: CountTrades นับ RECOVERY ด้วย ทำให้เปิด order ใหม่ไม่ได้
HIGH

สถานะ

FIXED

สิ่งที่เกิดขึ้น

CountTrades() นับ RECOVERY orders (จาก Opposite Martingale) รวมเข้าไปด้วย ทำให้ gi_328 สูงเกินจริง เมื่อ gi_328 > MaxTrades EA จะไม่เปิด order ใหม่เลย

วิเคราะห์ Root Cause

1
สมมติ MaxTrades = 15, มี BUY 8 orders + RECOVERY SELL 4 orders = จริงๆ 8 orders
2
CountTrades() return 8+4 = 12 (นับ RECOVERY ด้วย)
3
เช็ค gi_328 > 0 && gi_328 <= MaxTrades (12 <= 15) = true
4
แต่ถ้านับถูก = 8 (ไม่ RECOVERY) แล้ว 8 <= 15 ก็ยัง true
5
ปัญหาจริง: เมื่อ RECOVERY เยอะ เช่น BUY 10 + RECOVERY 8 = 18 > MaxTrades(15) = ไม่เปิด order ใหม่
6
ทั้งที่จริงๆ มีแค่ 10 regular orders ซึ่งยังไม่เกิน MaxTrades

โค้ดที่แก้ (บรรทัด ~1270-1290)

int CountTrades() { ... // ไม่มีการ filter RECOVERY if (PositionGetInteger(POSITION_TYPE) == POSITION_TYPE_SELL || PositionGetInteger(POSITION_TYPE) == POSITION_TYPE_BUY) l_count_0++; } int CountTrades() { ... string comment = PositionGetString(POSITION_COMMENT); if (StringFind(comment, "RECOVERY") >= 0) // เพิ่ม filter continue; if (PositionGetInteger(POSITION_TYPE) == POSITION_TYPE_SELL || PositionGetInteger(POSITION_TYPE) == POSITION_TYPE_BUY) l_count_0++; }

ผลกระทบ

เมื่อมี RECOVERY orders เยอะ EA จะคิดว่าถึง MaxTrades แล้ว ไม่เปิด Martingale order ใหม่ ทำให้ระบบ Martingale หยุดทำงานก่อนเวลาอันควร

Bug #5: Opposite Martingale Lot ไม่พอ cover loss
MEDIUM

สถานะ

FIXED

สิ่งที่เกิดขึ้น

Lot ของ RECOVERY order คำนวณจาก Lots * 1.2^existingOpposite ซึ่งเริ่มจาก 0.01 lot เสมอ ทำให้ RECOVERY order เล็กเกินไป ไม่สามารถ cover loss ที่เกิดขึ้นจริงได้

วิเคราะห์ Root Cause

1
Lots = 0.01 (base lot)
2
Layer 0: 0.01 * 1.2^0 = 0.01 lot
3
Layer 1: 0.01 * 1.2^1 = 0.012 lot
4
Layer 2: 0.01 * 1.2^2 = 0.0144 lot
5
ถ้า BUY loss อยู่ที่ -$500 (จาก 10 orders) RECOVERY 0.01 lot ต้องการ price move มหาศาลเพื่อ cover
6
ผลลัพธ์: RECOVERY lot เล็กเกินไป ไม่สามารถ recovery ได้จริง
